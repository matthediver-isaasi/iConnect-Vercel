---
name: Private report recovery
description: Distinguishing historical report content from current validation when private outputs disappear.
---

When a historical private report is missing, compare regenerated bytes against the original attachment's recorded content hash and size. A complete match establishes report-content identity, but not proof of individual database writes.

**Why:** A current-state regeneration can reproduce historical held rows exactly even though the original operational journal is unavailable. Merely finding existing members is not evidence that the original import created or updated them.

**How to apply:** Verify the pinned source, parse the actual delivered file, compare every source cell, and verify the new attachment registration matches those bytes. Keep historical exclusions, current validation, and unrecovered write outcomes separate. Missing local report files or attachment metadata alone do not establish what a previous download displayed.

Re-present recovered private reports from actual files in the main workspace, not merged attachment metadata alone.

**Why:** A task merge retained attachment metadata but omitted ignored private exports; the user reported blank downloads. Metadata hashes did not establish usable delivery.

**How to apply:** Reopen the main-workspace CSV/workbook, confirm populated rows and a visible first sheet, then register fresh attachments. Keep personal data out of Git and public hosting.
