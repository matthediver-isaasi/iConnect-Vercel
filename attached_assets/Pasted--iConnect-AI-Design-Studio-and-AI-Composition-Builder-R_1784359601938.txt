# iConnect AI Design Studio and AI Composition Builder

## Revised implementation scope

## 1. Project objective

Extend the existing iConnect Canvas Builder with an AI-assisted design system that allows customers to create visually compelling web pages, page sections, infographics and illustrations from natural-language prompts.

The feature should address the principal barriers organisations face when creating website content:

* Limited design and layout creativity
* Limited illustration and infographic capability
* Difficulty writing effective website copy
* Difficulty translating an idea into a polished responsive page
* Inconsistent application of organisational branding
* Lack of confidence when modifying complex page layouts

The AI should act as a designer, illustrator and copywriter operating inside the existing Canvas Builder.

The customer should describe what they need, review the generated result and continue directing changes through natural-language prompts.

Customers should not need to understand:

* HTML
* CSS
* Responsive design
* Visual hierarchy
* Illustration
* Graphic design
* Complex Canvas positioning

The finished content must remain part of the existing Canvas Builder page, draft, approval and publishing workflow.

---

# 2. Core architectural principle

Whole-page generation and individual AI section generation must use the same underlying architecture.

Do not build separate technical systems for:

* AI page creation
* AI section creation
* AI infographics
* AI heroes
* AI illustrations
* AI page redesign

Introduce a single first-class Canvas Builder element:

## AI Composition

An AI Composition is a self-contained, responsive design area that can represent either:

1. A single AI-generated page section, or
2. A multi-section composition representing most or all of a page body.

The scope of the AI Composition is determined by:

* Where it is inserted
* The available space
* Whether the Canvas page is blank
* The user’s prompt
* The creation mode selected
* The content before and after it
* The organisation’s branding
* Existing page purpose and context

### Example: blank Canvas page

A user adds an AI Composition to a blank page and prompts:

> Create a complete landing page for our annual conference, including a hero, event benefits, keynote speakers, programme overview, venue information, an abstract-submission infographic and registration calls to action.

The result may be:

```text
Canvas page
└── AI Composition
    ├── Hero section
    ├── Event introduction
    ├── Benefits section
    ├── Speaker section
    ├── Programme overview
    ├── Abstract process infographic
    ├── Venue section
    └── Registration call to action
```

The existing iConnect site navigation, footer, consent controls and other protected site infrastructure remain outside the AI Composition.

### Example: existing Canvas page

A user inserts an AI Composition between two existing Canvas elements and prompts:

> Create an engaging infographic explaining the membership application process. Match the design and tone of the rest of this page.

The result may be:

```text
Canvas page
├── Manual hero
├── Manual membership introduction
├── AI Composition
│   └── Membership application infographic
├── Existing membership form
└── Manual contact information
```

This mixed-content approach must be supported from the outset.

# 3. Product principle

The governing principle is:

> Customers direct the design; AI performs the design work.

Users should be able to explain:

* What they need
* What they want changed
* What content must be included
* What destination a button should use
* What style or feeling they want
* Which part of the composition they are referring to

The AI should remain responsible for:

* Composition
* Layout
* Alignment
* Spacing
* Responsive behaviour
* Typography hierarchy
* Illustration style
* Visual balance
* Decorative treatment
* Infographic design

The first release should not attempt to provide a complete Figma-style manual layer editor.

At the parent Canvas level, users must be able to:

* Add an AI Composition
* Add a complete AI page composition
* Add an AI-generated section
* Position the composition within the page
* Set its width
* Set a minimum height
* Allow automatic height
* Move it relative to other Canvas elements
* Duplicate it
* Hide it
* Delete it
* Preview it
* Ask AI to change it
* Create an alternative
* View its versions
* Restore a previous version
* Convert supported content where appropriate
* Insert standard Canvas elements before or after it

The AI Composition must participate in normal page flow.

It must not require the user to predict an exact fixed height before generation.

## Required outer layout behaviour

Support:

* Full available width
* Configurable width
* Minimum height
* Automatic content height
* Breakpoint-specific height
* Safe expansion
* Safe contraction
* Parent Canvas reflow
* No overlap with following Canvas elements
* Standard Canvas spacing before and after the composition

If the AI Composition becomes taller, subsequent Canvas elements must move down.

If it becomes shorter, the page should close the unused space safely.

# 5. AI Composition internal structure

An AI Composition must be stored as a structured design document.

It must not be stored only as:

* A screenshot
* A flattened image
* Opaque generated HTML
* An iframe
* Unstructured CSS
* Conversation history

The structured composition document must remain the source of truth.

## Multi-section structure

An AI Composition must support one or more internal section groups.

Conceptually:

```json
{
  "id": "ai_composition_uuid",
  "name": "Annual conference landing page",
  "compositionType": "multi_section_page",
  "status": "draft",
  "originalPrompt": "Create a complete annual conference page...",
  "sections": [
    {
      "id": "section_hero",
      "name": "Hero",
      "type": "ai_section",
      "elements": []
    },
    {
      "id": "section_benefits",
      "name": "Benefits",
      "type": "ai_section",
      "elements": []
    },
    {
      "id": "section_process",
      "name": "Abstract submission process",
      "type": "ai_section",
      "elements": []
    }
  ],
  "layouts": {
    "desktop": {},
    "tablet": {},
    "mobile": {}
  },
  "protectedValues": [],
  "generatedAssets": [],
  "conversation": [],
  "generationMetadata": {},
  "accessibility": {},
  "currentVersionId": "version_uuid"
}
```

## Selection hierarchy

Users must be able to target:

* The complete AI Composition
* An individual internal section
* A meaningful group within a section
* A particular content element

This should allow requests such as:

* “Give the whole page a more editorial style.”
* “Redesign only the speaker section.”
* “Add a sponsorship section between the programme and venue sections.”
* “Make this statistic the main focus.”
* “Replace this image.”
* “Change this button link.”
* “Make the mobile version of this section less crowded.”

# 13. AI generation workflow

Implement generation as a multi-stage server-side workflow.

## Stage 1: context assembly

Gather only relevant information from the current organisation:

* Brand settings
* Approved media
* Existing page context
* Relevant pages
* Relevant events
* Relevant forms
* Membership information
* User-supplied content
* Uploaded reference documents
* Available internal destinations
* Canvas dimensions
* User permissions
* Requested composition scope

Maintain strict tenant isolation.

## Stage 2: creative plan

Ask the model to produce an internal plan containing:

* Intended audience
* Primary action
* Content narrative
* Visual concept
* Number of proposed sections
* Section order
* Required imagery
* Proposed infographic or illustration
* Required functional components
* Information requiring verification
* Desktop approach
* Tablet approach
* Mobile approach

This plan may be retained for audit and later editing.

Do not expose private model reasoning.

## Stage 3: factual-content resolution

Before writing final copy, identify required factual content such as:

* Dates
* Prices
* Names
* Statistics
* Membership entitlements
* Event locations
* Registration details
* Sponsor information
* Form destinations

Retrieve these values from approved iConnect records or require user confirmation.

Do not allow the AI to invent them.

## Stage 4: content generation

Generate:

* Headings
* Supporting copy
* Button labels
* Captions
* Explanatory text
* Infographic labels
* Accessibility summaries
* Alt-text suggestions
* SEO-supporting content where applicable

Distinguish between:

* User-provided content
* Retrieved iConnect content
* AI-written promotional copy
* Potential factual claims requiring review

## Stage 5: design-document generation

Return a structured AI Composition document conforming to a strict schema.

Reject responses that do not validate.

Do not save invalid output as the active composition.

## Stage 6: image and illustration generation

Generate supporting assets where appropriate.

Store generated assets in the organisation’s existing media library.

Reference them by media asset ID.

## Stage 7: rendering and validation

Render the AI Composition at:

* Desktop
* Tablet
* Mobile

Run:

* Schema validation
* Security validation
* Missing-asset checks
* Broken-link checks
* Overflow checks
* Contrast checks
* Heading-order checks
* Alt-text checks
* Keyboard-interaction checks
* Responsive-layout checks
* Parent Canvas flow checks

## Stage 8: visual review

Where supported, provide rendered previews to a vision-capable model for review.

Check for:

* Text collisions
* Poor spacing
* Weak hierarchy
* Awkward image crops
* Excessive density
* Repetitive design
* Unbalanced layouts
* Mobile failures
* Weak calls to action
* Contrast problems
* Inconsistent section transitions

Allow a limited number of automated correction cycles.

## Stage 9: user preview

Present the proposed result.

Allow the user to:

* Insert
* Apply
* Request changes
* Create alternative
* Discard
* Preview desktop
* Preview tablet
* Preview mobile
* Review warnings
* Review factual claims
* Review generated assets

# 15. Patch-based changes

Minor changes must be applied as structured patches against the current composition.

Example:

```json
[
  {
    "operation": "update_content",
    "elementId": "heading_01",
    "changes": {
      "text": "Join the conversation shaping our profession"
    }
  },
  {
    "operation": "update_action",
    "elementId": "button_01",
    "changes": {
      "actionType": "event_registration",
      "eventId": "event_uuid"
    }
  }
]
```

Do not regenerate a full page or full section for a simple wording, link or image change.

## Supported change scopes

### Content-only

Preserve layout except where minor adjustment is needed for text length.

### Asset change

Replace or edit an image while preserving surrounding composition.

### Layout change

Change position or structure while preserving content and bindings.

### Section redesign

Replace the visual composition of one section while preserving protected values.

### Complete creative redesign

Create a substantially different complete composition while preserving protected values.

Major redesigns should default to creating an alternative rather than replacing the current version immediately.

# 18. Responsive behaviour

Every AI Composition and internal section must support:

* Desktop
* Tablet
* Mobile

The AI must create responsive reinterpretations rather than simply scaling down the desktop composition.

Examples:

* Horizontal timelines become vertical.
* Overlapping cards become stacked.
* Decorative imagery may be removed.
* Text may be shortened where approved.
* Buttons may become full-width.
* Statistics may become sequential.
* Complex illustrations may be simplified.
* Image focal points may change.
* Section order may change where semantically appropriate.

Prompting must support:

* Update all breakpoints
* Desktop only
* Tablet only
* Mobile only

A breakpoint-specific change must not unintentionally overwrite other breakpoints.

# 21. Rendering and CSS isolation

AI Compositions should render within the normal page DOM so content remains:

* Searchable
* Accessible
* Responsive
* Indexable
* Selectable
* Editable through AI
* Translatable in future

Avoid using an iframe as the standard renderer.

Avoid flattening complete compositions into image files.

## CSS isolation

All AI Composition styling must be scoped to the component instance.

Generated styles must not:

* Modify global page styles
* Modify navigation
* Modify footer
* Override other Canvas elements
* Affect admin interfaces
* Access elements outside the composition
* Load external stylesheets

Use:

* Unique component wrappers
* Validated style properties
* CSS property allowlists
* Sanitised values
* Scoped selectors

## JavaScript

Arbitrary generated JavaScript is prohibited in the first release.

Approved interactions must use existing iConnect actions or a controlled interaction library.

# 35. Acceptance criteria

## Blank-page whole composition

* A user can create a blank Canvas page.
* A user can add an AI Composition.
* A whole-page prompt creates a multi-section composition.
* The composition automatically sizes the page body.
* Internal sections can be selected independently.
* The user can add, remove, reorder or redesign sections through prompts.
* Navigation and footer remain protected outside the composition.
* The page remains in the normal draft workflow.

## Existing-page AI section

* A user can insert an AI Composition between existing Canvas elements.
* The AI receives relevant surrounding-page context.
* The generated section complements the existing page.
* The composition auto-height pushes later content down safely.
* Existing manual elements remain unchanged.
* The AI section can be modified independently.

## Mixed content

* A page can contain manual elements, AI Compositions and standard functional components.
* AI changes do not damage standard components.
* Standard forms, event components and membership components remain authoritative.
* AI may visually support but not recreate protected functionality.

## Creativity

* The system can create layouts beyond the existing component library.
* It supports layering, irregular composition, infographic structures and generated illustration.
* Different directions produce meaningfully different designs.
* Whole pages do not appear as a repetitive stack of fixed templates.

## Prompted editing

* Users can target the complete composition, a section or an internal element.
* Prompts reliably affect the selected scope.
* Minor changes use patches.
* Major changes may create alternatives.
* Protected values remain intact.
* Users can accept, reject or refine changes.

## Responsive behaviour

* Desktop, tablet and mobile layouts are separately represented.
* Mobile is not merely scaled desktop.
* Breakpoint-specific prompts are supported.
* Parent Canvas flow remains correct at every breakpoint.

## Links

* Internal destinations use record IDs.
* AI does not invent internal URLs.
* Ambiguous destinations present valid choices.
* Broken destinations are identified.

## Images

* Generated images are stored in the media library.
* Existing images can be used.
* Images can be replaced through prompting.
* Alt text is available or flagged.
* Essential text is not embedded only in images.

## Accessibility

* Semantic reading order exists.
* Links and buttons are keyboard accessible.
* Contrast failures are detected.
* Missing alt text is detected.
* Critical failures block approval.

## Versioning and safety

* Every accepted AI operation creates a version.
* Previous versions can be restored.
* Failed generations do not replace valid content.
* AI output is never automatically published.
* All operations are auditable.

## Security

* API keys remain server-side.
* Output is schema validated.
* Unsafe markup is rejected.
* Scripts and external-resource injection are blocked.
* Tenant boundaries are enforced.
* Existing permissions are enforced.

## Usage controls

* AI usage is recorded.
* Organisation allowances are configurable.
* Image usage is separated from text and layout usage.
* Accidental duplicate submissions are prevented.
