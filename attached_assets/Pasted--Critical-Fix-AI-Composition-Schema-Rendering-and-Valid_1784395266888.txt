# Critical Fix: AI Composition Schema, Rendering and Validation

## Current failure

The AI Composition generator produced unusable HTML in which:

* Every visible element is absolutely positioned at `left: 0; top: 0`.
* The section has `min-height: 0`.
* The intended flex container is empty.
* Content elements are rendered outside the container.
* Numeric CSS values such as `font-size: 24` and `border-radius: 8` have no units.
* The background has no width or height.
* The call to action is rendered as `<span role="presentation">`.
* No requested imagery, illustrations, cards or graphic composition were produced.
* Desktop, tablet and mobile repeat the same invalid layout.
* The outer Canvas block uses `overflow: hidden`, clipping the zero-height composition.

This is a composition-pipeline failure, not a prompt-quality problem.

Do not attempt to solve it by rewriting the user prompt.

# 2. Fix parent-child hierarchy

Every internal element must have an explicit parent relationship.

Use one consistent structure, for example:

```json
{
  "id": "container_intro",
  "type": "container",
  "children": [
    "heading_intro",
    "paragraph_intro",
    "button_intro"
  ]
}
```

or:

```json
{
  "id": "heading_intro",
  "type": "heading",
  "parentId": "container_intro"
}
```

Do not support ambiguous mixtures unless they are normalised before rendering.

Validate that:

* Every non-root element has a valid parent.
* Parent IDs exist.
* Circular relationships are rejected.
* An element appears under only one parent.
* Container children render inside the container DOM node.
* Child order is preserved.
* Nested groups and sections render recursively.
* Orphaned elements cause validation failure.

The renderer must produce:

```html
<div class="aic-e-container_intro">
  <h2>...</h2>
  <p>...</p>
  <a>...</a>
</div>
```

not:

```html
<div class="aic-e-container_intro"></div>
<h2>...</h2>
<p>...</p>
```

# 3. Separate flow layout from absolute layout

Every container must explicitly declare a layout mode:

* `flow`
* `flex`
* `grid`
* `absolute`

## Flow, flex and grid containers

Children must remain in document flow by default.

Do not emit:

```css
position: absolute;
left: 0;
top: 0;
```

for children of flow, flex or grid containers.

Example:

```json
{
  "layout": {
    "mode": "flex",
    "direction": "column",
    "gap": 16,
    "align": "start"
  }
}
```

should render with normal flex children.

## Absolute containers

Absolute positioning may be used only when every visible child has valid breakpoint-specific geometry:

* `x`
* `y`
* `width`
* `height` or content-height behaviour
* Layer order where needed

Example:

```json
{
  "layout": {
    "mode": "absolute",
    "height": 640
  },
  "geometry": {
    "desktop": {
      "x": 84,
      "y": 120,
      "width": 420,
      "minHeight": 90
    }
  }
}
```

Do not default missing absolute coordinates to zero.

Missing required absolute geometry must cause schema or validation failure.

---

# 4. Remove dangerous zero defaults

Do not normalise absent layout values to:

```json
{
  "x": 0,
  "y": 0,
  "minHeight": 0
}
```

Use `null` or omit the property.

A missing value and an intentional zero are not equivalent.

For example:

* `x: 0` may be intentional.
* Missing `x` means the layout is incomplete.
* `minHeight: 0` may be valid in normal flow.
* An absolute section containing visible children cannot safely use zero height.

Reject incomplete absolute layouts instead of silently converting missing data to zero.

---

# 5. Fix length-unit serialisation

Create a central CSS value serialiser.

Numeric values for dimensional properties must receive appropriate units.

Properties requiring `px` by default include:

* `font-size`
* `line-height` where stored as an absolute measurement
* `border-radius`
* `border-width`
* `width`
* `height`
* `min-width`
* `min-height`
* `max-width`
* `max-height`
* `top`
* `right`
* `bottom`
* `left`
* `gap`
* `padding`
* `margin`
* `letter-spacing`
* `outline-width`
* `stroke-width` where appropriate

Example:

```typescript
const LENGTH_PROPERTIES = new Set([
  "font-size",
  "border-radius",
  "width",
  "height",
  "min-height",
  "top",
  "left",
  "gap"
]);

function serializeCssValue(
  property: string,
  value: unknown
): string | null {
  if (value === null || value === undefined) return null;

  if (
    typeof value === "number" &&
    LENGTH_PROPERTIES.has(property)
  ) {
    return `${value}px`;
  }

  return String(value);
}
```

Support explicit alternative units only through a validated representation:

```json
{
  "value": 100,
  "unit": "%"
}
```

Never output invalid declarations such as:

```css
font-size: 24;
border-radius: 8;
```

Add unit tests for every supported style property.

# 6. Define section sizing rules

A section must use one of:

## Content-flow height

The section’s height is determined by normal-flow children.

## Explicit absolute-canvas height

The section has a positive height for each breakpoint.

## Calculated absolute height

The renderer calculates the lower boundary of all positioned children plus section padding.

For an absolute section:

```typescript
calculatedHeight =
  max(child.y + child.height) +
  sectionPaddingBottom;
```

Use the explicit height where supplied and valid.

Reject any section where:

* It contains visible absolute children, and
* Its resolved height is zero or missing.

The Canvas parent should use the resolved composition height so later blocks reflow correctly.

---

# 7. Fix backgrounds

Background elements must use a defined layout strategy.

For a section background, prefer styling the section or container itself.

Where a separate background layer is necessary, render:

```css
position: absolute;
inset: 0;
```

or provide complete geometry.

Do not emit a background layer with only:

```css
left: 0;
top: 0;
```

Background layers must also be:

* `aria-hidden="true"`
* Non-interactive
* Behind content
* Excluded from semantic reading order

---

# 8. Render semantic interactive elements

A call to action must be a real semantic element.

Use:

```html
<a href="...">Learn more</a>
```

for navigation, or:

```html
<button type="button">...</button>
```

for an application action.

Never render a CTA as:

```html
<span role="presentation">
```

The structured element must contain an approved action:

```json
{
  "type": "button",
  "label": "What happens at an appointment?",
  "action": {
    "type": "internal_page",
    "pageId": "..."
  }
}
```

Where the destination has not yet been resolved, render a disabled editor-state placeholder and prevent approval until it is resolved.

## Element requirements

Require:

* `id`

* Breakpoint visibility

## Absolute element requirements

Conditionally require:

* Desktop geometry

## Container requirements

Require:

* Layout mode
* Child IDs
* Padding
* Gap where relevant
* Width behaviour
* Alignment

Do not allow the model to return style fragments without a complete structural relationship.

# 12. Add deterministic layout validation

After rendering, inspect computed DOM geometry.

For every visible element collect:

* Bounding rectangle
* Computed display
* Computed position
* Visibility
* Opacity
* Overflow clipping
* Parent rectangle
* Z-index

Reject or warn when:

## Zero-size elements

* Width is zero
* Height is zero
* Area is effectively zero

## Severe overlap

Calculate pairwise overlap between visible semantic elements.

Reject when multiple text elements overlap by more than a small threshold unless the composition explicitly marks the overlap as intentional.

The current output should be rejected because all text elements share the same origin.

## Off-canvas elements

Reject important elements mostly outside the section bounds.

## Clipped elements

Reject important elements clipped by section or Canvas overflow.

## Empty containers

Warn or reject layout containers that:

* Have expected children, but
* Render no child DOM nodes.

## Blank composition

Reject a composition whose visible area is effectively blank.

## Unreasonable density

Warn where too many text elements occupy the same small region.

* Hierarchy from structured composition is preserved in the DOM.
* Flex and grid children are not absolutely positioned.

* Numeric CSS lengths receive units.

* Prompt-required visual elements are present.

* The Composition Inspector shows the full generation pipeline.
