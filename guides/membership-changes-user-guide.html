Changing or cancelling a membership

A guide for members and membership administrators
Prepared by Replit Agent · 28 October 2026 · Current implementation for preview testing

The key distinction: requesting a change, approving it, completing its financial arrangements and applying the new membership are separate stages. An approval message does not mean that a payment or refund has happened.

1. What is now available?

Members can request a change to their membership through an enabled membership-change form. Administrators can review the request and use its saved financial details to process the change.

Supported processing includes additional-payment invoices, eligible member credit, refund handling and changes to supported monthly payment arrangements. Administrators also have cancellation controls, with separate handling of access and the final financial balance.

The system retains the original purchase and records the change separately, so the membership team can see what was requested, approved and applied.

2. How a member requests a change

  1. Sign in and open the membership-change form provided by your membership team.
  2. Choose an offered membership structure and, where relevant, the appropriate pricing band. Enter the reason for the change.
  3. Select Preview request. Check the proposed membership, dates and any available financial figures.
  4. Confirm that you have reviewed the information, then select Submit for review.
  5. Check the request history for progress. A pending request can be withdrawn before it is approved.

Submitting a request does not immediately change the membership or take payment. If the form reports missing information or an unresolved existing change, contact the membership team rather than submitting duplicate requests.

Current release: all member-submitted changes still require administrator review, even where the organisation's saved policy allows automatic approval. Automatic approval is not yet connected.

3. How an administrator processes a request

  1. Open the member's record and select the Membership tab. Processing controls require the appropriate administration and finance permissions.
  2. Review the member's request. Record a reason for approving or rejecting it and confirm your decision.
  3. For an approved request, select Review financial processing. This takes you to the financial controls for that specific approved change.
  4. Check the proposed membership, dates, financial treatment and any warnings. Select a permitted treatment where a choice is offered.
  5. Enter the required financial approval reason and explicitly confirm processing. This is separate from approving the member's initial request.
  6. Monitor the result. Payment, refund or provider checks may still be outstanding before the change can be applied.

For an administrator-led change, use the preview and confirmation controls in the Membership tab. Always work from the current saved proposal rather than creating another proposal to get around a processing warning.

4. How money and membership dates are handled

If an additional amount is due

The supported financial flow creates the additional invoice. The change remains pending until the required settlement has been verified. Creating an invoice is not evidence that it has been paid.

If there is eligible unused value

The available treatment depends on the organisation's policy and verified payment history:

  • Member credit: eligible value can become personal credit held in iConnect, with the corresponding accounting records. Any expiry follows the configured policy; the default is no expiry.
  • Refund: refund handling requires a separately completed, recorded and bank-reconciled refund. Selecting this option does not automatically send money back to a card or bank account.

A credit note is an accounting adjustment. It is not, on its own, proof of either a cash refund or spendable member credit.

If there is no financial difference

A supported change can proceed without an extra collection or refund, but it still requires confirmation and successful application.

Monthly payments

Supported monthly card and Direct Debit changes use the saved membership and payment arrangement. Do not assume that editing a price elsewhere automatically updates an existing card agreement.

For cancellation, unpaid future instalments are not treated as money already received. For variable monthly Direct Debit, service periods follow the membership-start anniversaries, not the dates on which collections happened.

Renewal date

A supported change can retain the existing renewal date or start a replacement term, as permitted by the configured change rules. Check the dates in the preview: an upgrade does not automatically mean a fresh twelve-month membership.

5. Cancelling a membership

Cancellation is currently an administrator action in the member's Membership tab, not a member self-service option.

  1. Enter the cancellation reason and preview it.
  2. Check the effective date. The organisation's cancellation policy determines whether it takes effect immediately or at the end of the term.
  3. Explicitly confirm the cancellation.
  4. Review cancellation finances separately using Preview cancellation finances, then approve the permitted financial treatment.
  • Immediate cancellation ends membership access immediately. A balance for service already used may remain payable.
  • A scheduled cancellation can be withdrawn before access has ended. Withdrawal keeps the history; it does not erase the original request.
  • Once access has ended, withdrawal cannot restore it.
  • Paying an old outstanding invoice does not restart a cancelled membership.
  • Ending access does not mean that all payment-provider or accounting checks are complete.

Background processing supports scheduled cancellations and recovery. Separate notifications distinguish membership access ending from the final financial balance being resolved. Neither notification should be assumed sent until delivery is confirmed.

6. Understanding progress messages

MessageWhat it means
Pending reviewThe membership team has not yet approved or rejected the request.
Approved for processingThe request is approved, but financial processing or application has not been confirmed.
Processing / applyingWork is in progress. Do not assume the new membership is active yet.
Awaiting paymentThe required payment has not yet been verified.
Awaiting refundThe refund still needs to be completed and verified.
Awaiting reconciliationThe team needs to verify an existing financial or payment-provider outcome before proceeding.
Membership change appliedThe new membership has been applied. This label alone is not a cash-refund receipt.
Processing status unavailableThe latest position could not be loaded. Refresh or contact the team; it does not mean processing failed or completed.

If a screen times out: use the recovery or refresh action first. The original operation may already exist. Do not create a second request or repeat a payment/refund simply because the response was lost.

7. Making a change form available

In FormBuilder, save an active form that requires members to sign in. Enable its membership-change settings, choose the membership structures it may offer and save those settings. Give members the resulting form link.

Enabling the form does not change existing memberships or start billing. It makes the request journey available to members who are allowed to access that form.

8. Cases still needing attention

  • Automatic policy-based approval: not yet connected; administrators must review member requests.
  • Member self-service cancellation: not yet available; the membership team must use the admin controls.
  • Cancellation funded by original vouchers or organisation money: the original-owner return process is not complete. Do not convert that funding into personal cash or credit as a workaround.
  • Some variable Direct Debit collections: an unsubmitted collection or missing accounting evidence can block the financial outcome pending investigation.

Unknown amounts are not zero balances. Where records cannot establish the correct outcome, the system stops financial processing rather than guessing.

Testing recommendation: start with clearly documented test memberships and test payment/accounting arrangements. Check the original membership, requested change, financial documents and final membership together. A preview branch alone should not be assumed to isolate live payments, emails or accounting records.
