1. What an event microsite does

A microsite groups public pages under one URL prefix and gives them their own navigation, header, footer and optional branding.

Example URL pattern

/northstar-2026 → selected home page

/northstar-2026/agenda → agenda page

/northstar-2026/venue → venue and travel page

Microsite versus event management

Use the microsite forUse event management for
Overview and promotional contentEvent record, dates and operational status
Agenda presentation and speaker storiesSessions, tracks and speaker assignments
Venue, travel, sponsors and FAQsTickets, prices, eligibility and capacity
Clear links to registrationRegistration, payment and attendee records
Event-specific navigation and brandingConfirmations, check-in and attendance
Important: the microsite does not create or manage the event. Build the operational event and registration journey in the event area, then link to it from the microsite.

Prerequisites

  • Permission to use Microsites and the page editor.
  • Final event name and a short, durable URL prefix.
  • Approved logos, colours, social image and sponsor assets.
  • The correct event registration URL.
  • A colleague who can test while signed out on desktop and mobile.
Choose the URL once. A prefix uses lowercase letters, numbers and hyphens and must be one segment. Changing it later changes every microsite page address.

7. Brand the microsite (continued)

Footer choices

Footer sourceBehaviourUse when
Inherit main-site footerUses the main site’s effective footer, including its reusable Canvas footer.Legal and contact content should stay identical.
Configured microsite footerUses the event footer when Footer Configuration override is enabled.The event needs its own columns, colours or contact details.
Reusable Canvas footerRenders the selected reusable footer; later footer-editor changes flow through.A designed event footer already exists.

Accessible event branding

  • Keep text readable against every header and footer background.
  • Check the logo at mobile width and at the scrolled size if shrink-on-scroll is enabled.
  • Use a 1200×630 share image with event name, date and location.
  • Do not place essential information only inside an image.
  • Check Login and Member Area states if the Account element is included.
When reusable Canvas footer is selected, choose a footer before saving. When configured microsite footer is selected, turn on the Footer Configuration override.

9. Preview, test and launch

Launch order

  1. Finish and save all content.
  2. Assign every page and verify its new URL.
  3. Choose the home page.
  4. Build navigation with prefixed paths.
  5. Apply branding and microsite typography.
  6. Publish the pages.
  7. Switch the microsite Active on.
  8. Test while signed out, on desktop and mobile.
  9. Only then distribute links and QR codes.
Preview is not publication. Preview as visitor lets an authorised editor inspect a draft. Ordinary visitors still need an active microsite and a published page.

Launch checklist

Base URL opens the intended home page.
Every promoted page is assigned and published.
No old bare-slug URL is used.
Header, dropdown and footer links work.
Registration buttons open the right event.
Search scope behaves as intended.
Logo links to the home page.
Mobile text and controls are readable.
Social sharing text and image are suitable.
Venue and accessibility details are correct.
Signed-out visitors can use public pages.
No confidential draft content is visible.

10. Promote and operate the event

Promotion

Use the base URL in general promotion and deep links for agenda, venue or FAQs when useful. Generate QR codes only after the prefix and slugs are final.

Day-of use

  • Keep urgent agenda and venue updates short and prominent.
  • Put high-priority updates near the top of the overview.
  • Re-test registration links if ticket availability changes.
  • After editing, save and confirm the public page.
  • Use event management—not the microsite—for bookings, attendee records, check-in and attendance.
Content update workflow

Open page editor → make change → Save → Preview as visitor → confirm public page → notify attendees if needed

Search and navigation help visitors find published content. They never override the page’s publication state or the microsite’s Active state.

Useful handover record

Record the prefix, base URL, home page, page owners, event registration URL, retirement date, and person responsible for post-event content.

11. Retire the microsite safely

Do not delete immediately after the event. Old emails, bookmarks and QR codes may still be in use.

Recommended retirement

  1. Replace the overview with a post-event message and useful next steps.
  2. Remove or update registration calls to action.
  3. Keep recap, sponsor and venue information only as long as required.
  4. Unpublish pages that should no longer be public.
  5. At the end of the archive period, switch Active off.
  6. Check campaigns, QR codes and external links before deletion.

Inactive versus delete

ActionResultRecommendation
InactiveThe microsite stops resolving publicly; its structure remains available to administrators.Preferred for normal post-event retirement.
DeleteNavigation is deleted and pages return to the default site at their bare slugs.Use only after reviewing every page and inbound link.
Deletion cannot be undone from this screen. Still-published pages may become available at new bare addresses. Unpublish or review every assigned page first.

12. Troubleshooting

A page shows “not found”

Confirm the microsite is active, the page is assigned and published, and the address uses /{prefix}/{slug}.

The base URL does not show the overview

Edit the microsite, select an assigned page under Home page, save and retest.

A page disappeared from the main site

This is expected after assignment. Its address moved from /{slug} to /{prefix}/{slug}.

Branding looks like the main site

Enable Override for the required card, set the values and select Save branding. Non-overridden sections intentionally inherit.

A navigation link opens the wrong place

Use the complete prefixed path, confirm the current page slug and ensure the item is active.

Search includes unwanted main-site results

Edit the Search header element and restrict it to this microsite. The Search element must be present in navigation.

Five facts to remember

  1. Active microsite + published page = public availability.
  2. Assignment changes the page address.
  3. Home page selection enables the short base URL.
  4. Microsite navigation replaces tenant navigation.
  5. Inactive is usually safer than delete after an event.
